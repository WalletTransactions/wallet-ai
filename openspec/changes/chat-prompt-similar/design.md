## Context

Промпт chat живёт в `prompts/chat.txt` (chat-v3, change `chat-prompt-v3`).
wallet-mcp 0.3.7 отдаёт `similar` в нулевых строках `spending_by_category` и
`spending_by_category_by_month`: `[{category, amount, count}]`, не больше
пяти, `[]` — «проверено, ничего нет». Описание инструмента фразу про
`similar` уже содержит, но на test 8B-модель ответила «0 евро».

## Goals / Non-Goals

**Goals:** модель при нулевой категории с непустым `similar` отвечает по
суммам похожих категорий, а не «0».

**Non-Goals:** менять wallet-mcp (поле и описание готовы), менять таблицу тем,
писать код в `src/chat.cpp`.

## Decisions

**D1. Правило в системном промпте, а не код сервиса.** Агентный цикл
универсален и не знает формата ответов инструментов; промпт — то место, где
уже живут правила chat-v3 (имена, `exclude_categories`, месяцы, поиск).

**D2. Повторный вызов с именами из `similar`, а не пересказ полей.**
Складывать суммы в уме запрещает уже действующее «не считай в уме то, что
может посчитать инструмент». Поэтому модель вызывает инструмент ещё раз с
`categories` из `similar` и тем же периодом и берёт `total` из ответа.
Альтернатива «назвать суммы из `similar` по отдельности» оставлена как запасной
вариант в тексте правила: одна категория в `similar` — повторный вызов не нужен.

**D3. Версия `chat-v4`.** Текст изменился — по шапке файла версию поднимаем;
тест на реальный файл ждёт новую версию и слово `similar`.

**D4. Пустой `similar` — отдельная фраза.** `similar: []` — «проверено»;
модель отвечает, что расхода по теме нет, а не гадает.

## Risks / Trade-offs

- [8B-модель снова не применит правило] → проверка живым вопросом на test;
  если не помогло с двух попыток, записать как «качество модели» (как D7
  `chat-prompt-v3`), не усложнять промпт.
- [Правило удлиняет промпт при контексте 16384] → одно-два предложения.

## Migration Plan

rc-тег wallet-ai на test, проверка вопросом про кафе. Prod — обычным потоком
rc-тегов после проверки. Откат — предыдущий образ или прежний `chat.txt`.
