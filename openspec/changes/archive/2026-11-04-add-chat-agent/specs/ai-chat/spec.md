# Spec Delta

## Purpose

Ответы на вопросы о кошельке свободным текстом: задание `chat` ведёт
агентный цикл с выбранной моделью, а данные берёт только через инструменты
wallet-mcp. Ничего не записывает и не отдаёт модели токены.

## ADDED Requirements

### Requirement: Вход задания chat
`POST /api/ai/jobs` с `kind: chat` SHALL принимать `input` с `text` (1..1000
байт UTF-8), необязательным `conversation_id` (1..64 символа `[A-Za-z0-9_:-]`)
и необязательным `now` (`date` `ГГГГ-ММ-ДД`, `time` `ЧЧ:ММ:СС` в поясе
пользователя). Нарушение — 400 с текстом проверки (схема — `openapi.yaml`,
`ChatInput`).

#### Scenario: Вопрос из бота
- **WHEN** бот создаёт задание `chat` с `text` «сколько за няню» и `conversation_id` `tg-42-1`
- **THEN** ответ 202 `{"job_id", "status": "queued"}`

#### Scenario: Пустой текст
- **WHEN** `input.text` пустой или длиннее 1000 байт
- **THEN** ответ 400, задание не создаётся

### Requirement: Результат задания chat
Задание `chat` SHALL завершаться `done` с `result`: `text` (ответ модели,
обычный текст), `conversation_id`, `provider` (`lmstudio` или `claude`),
`steps` (число вызовов модели) и `tools` (имена вызванных инструментов по
порядку). Если `conversation_id` во входе не было, сервис создаёт новый и
возвращает его.

#### Scenario: Ответ с вызовом инструмента
- **WHEN** модель вызвала `spending_by_category` и затем дала текст
- **THEN** `result.text` — этот текст, `result.tools` = `["spending_by_category"]`, `result.steps` = 2

### Requirement: Инструменты только через wallet-mcp
Сервис SHALL предлагать модели ровно инструменты из `tools/list` wallet-mcp
и исполнять вызовы модели только через `tools/call` wallet-mcp с токеном,
выданным для wallet-mcp. Модель не получает токенов, адресов сервисов и
`user_id`. Вызов инструмента, которого нет в списке, возвращается модели как
ошибка инструмента и в wallet-mcp не уходит.

#### Scenario: Модель выдумала инструмент
- **WHEN** модель просит `delete_operation`
- **THEN** модели возвращается ошибка «нет такого инструмента», wallet-mcp не вызывается, цикл продолжается

#### Scenario: Ошибка инструмента
- **WHEN** wallet-mcp отвечает `isError` со списком похожих категорий на «Няня»
- **THEN** текст ошибки возвращается модели как результат инструмента, и модель может вызвать инструмент снова

### Requirement: Пределы цикла
Цикл SHALL делать не больше `AI_CHAT_MAX_STEPS` (5) вызовов модели. Если
после предела модель всё ещё просит инструменты, сервис делает один
дополнительный вызов без инструментов и просит ответить по полученным
данным. Всё задание ограничено `AI_JOB_TIMEOUT_SECS_CHAT` (120 с); по
истечении — `failed: timeout`.

#### Scenario: Модель не останавливается
- **WHEN** модель на каждом из 5 шагов просит инструмент
- **THEN** шестой вызов идёт без инструментов, его текст — результат, `steps` = 6

#### Scenario: Дедлайн
- **WHEN** вызовы модели и инструментов в сумме длятся дольше 120 с
- **THEN** задание `failed` с `failure: timeout`

### Requirement: Отказы задания chat
Задание `chat` SHALL завершаться `failed` с `failure`:
- `tools_unavailable` — wallet-mcp недоступен или ответил `503`;
- `auth_expired` — wallet-mcp ответил `401`;
- `provider_auth_failed` — провайдер отказал в ключе;
- `provider_refused` — модель отказалась отвечать;
- `unavailable` — провайдер недоступен;
- `timeout`, `internal` — как у других видов.

#### Scenario: wallet-mcp лежит
- **WHEN** wallet-mcp не отвечает на `tools/list`
- **THEN** задание `failed` с `failure: tools_unavailable`, модель не вызывается

### Requirement: Токен для wallet-mcp при создании
При создании задания `chat` сервис SHALL обменять JWT пользователя в
google-auth на токен для wallet-mcp (`/internal/token/exchange`, actor
`wallet-ai`, `audience=wallet-mcp`) и держать его только во входе задания в
памяти. Отказ обмена — 401 `{"error":"invalid_token"}`, недоступный
google-auth — 503 `{"error":"unavailable"}`, задание не создаётся.

#### Scenario: Обмен прошёл
- **WHEN** бот создаёт задание `chat` своим токеном пользователя
- **THEN** google-auth вызван один раз, задание создано, токен не попадает в снимок задания и журнал

### Requirement: История диалога
Сервис SHALL хранить в памяти по паре (пользователь, `conversation_id`)
вопросы и итоговые ответы, не больше `AI_CHAT_HISTORY_TURNS` (6) пар, и
удалять их через `AI_CHAT_HISTORY_TTL_SECS` (1800) после последнего
обращения. Следующее задание с тем же `conversation_id` получает их перед
новым вопросом. Результаты инструментов в историю не попадают.

#### Scenario: Уточнение периода
- **WHEN** на «сколько за няню» модель ответила «За какой месяц?», и пользователь в том же диалоге пишет «сентябрь»
- **THEN** модель получает оба прежних сообщения и вызывает `spending_by_category` с `from` 2026-09-01, `to` 2026-09-30

#### Scenario: Чужой диалог
- **WHEN** пользователь B передаёт `conversation_id` пользователя A
- **THEN** B получает пустую историю, реплики A ему не видны

### Requirement: Чат включается конфигурацией
Вид `chat` SHALL работать только при заданных `WALLET_MCP_URL` и
`AUTH_EXCHANGE_SECRET`. Без любой из них создание задания `chat` отвечает 503
`{"error":"unavailable"}`, а `parse_expense` и импорт работают как раньше.

#### Scenario: Нет адреса wallet-mcp
- **WHEN** `WALLET_MCP_URL` пуст, и бот создаёт задание `chat`
- **THEN** ответ 503 `{"error":"unavailable"}`, google-auth не вызывается

### Requirement: Приватность чата
Журнал и метрики задания `chat` SHALL содержать только id, провайдера,
имена инструментов, число шагов, токенов, длительности и исход. Текст
вопроса, ответа, аргументы и результаты инструментов в журнал не попадают.

#### Scenario: Запись о завершении
- **WHEN** задание `chat` завершилось
- **THEN** в журнале `job_id`, `user_id`, `provider`, `steps`, `tools`, `input_tokens`, `output_tokens`, `run_ms`, но не текст вопроса и не суммы
