# Proposal

## Why

Задание `chat` на GTX 1070 генерирует ответ 2–13 с и дольше (несколько шагов
модели плюс вызовы инструментов). Клиент всё это время видит пустоту и получает
ответ одним куском через long-poll. Нужен побуквенный вывод: текст появляется
по мере генерации, а вызовы инструментов видны как статус.

## What Changes

- Новый маршрут `GET /api/ai/jobs/{id}/events` — поток `text/event-stream` по
  заданию `chat`: события `delta` (кусок текста), `tool` (вызов инструмента и его
  исход), `done` (итог), `error`. Поддержка `Last-Event-ID` для переподключения.
- Задание `chat` ведёт журнал событий в памяти; поток читает журнал, а не
  держит LLM. Обрыв соединения клиента задание не отменяет.
- LLM-клиенты (LM Studio/OpenAI-совместимый и Claude) переходят с `stream:false`
  на потоковый разбор дельт текста и tool_calls для задания `chat`. Остальные
  виды заданий остаются без стриминга.
- Лимит одновременных потоков, чтобы не съесть пул потоков cpp-httplib.
- `GET /api/ai/jobs/{id}` и long-poll не меняются: итог по-прежнему доступен
  обычным путём, клиенты без SSE продолжают работать.
- Зависимости вне wallet-ai (отдельные изменения, здесь не делаются):
  потоковый прокси в wallet-gateway (сейчас ответ буферизуется целиком),
  SSE-клиенты в wallet-telegram, wallet-web и android-wallet.

## Capabilities

### New Capabilities
- `ai-chat-stream`: потоковая выдача хода задания `chat` по SSE — формат
  событий, журнал и переподключение, лимиты потоков, поведение при отмене и сбое.

### Modified Capabilities
- `ai-chat`: ход задания `chat` публикует события в журнал; приватность —
  текст дельт не попадает в логи.
- `ai-providers`: провайдеры умеют потоковую генерацию (дельты текста и
  tool_calls) для задания `chat`.

## Impact

- Код wallet-ai: `llm_client.cpp`, `chat_models.cpp` (потоковый разбор),
  `chat.cpp` (публикация событий), `jobs.cpp/hpp` (журнал событий), `ai.cpp`
  (маршрут), `openapi.yaml`, `README.md`, тесты с FakeLlm.
- wallet-gateway: нужен потоковый прокси для `text/event-stream` (без буфера,
  без `max_timeout`) — отдельное изменение, блокирует выкладку на внешний трафик.
- Клиенты (бот, web, Android) — отдельные изменения; web: `EventSource` не
  передаёт Authorization, нужен fetch-стрим.
- Порядок: после `enable-claude-provider`, чтобы потоковый разбор Claude делался
  один раз поверх готового провайдера.
- GPU: число токенов и время генерации не растут, меняется только момент отдачи.
