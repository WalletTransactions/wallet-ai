# Spec Delta

## Purpose

Профиль формата выписки — подсказки и примеры для конкретного банка или
шаблона документа. Они подмешиваются в промпт извлечения и в проверку кодом.
Профили бывают встроенные (файлы в репозитории) и свои у пользователя — те
пополняются примерами из его правок.

## ADDED Requirements

### Requirement: Встроенные профили
Сервис SHALL загружать при старте профили из `prompts/banks/*.txt`. Каждый файл
содержит `# version:`, `id`, `name`, сигнатуры, подсказки модели, до 3 примеров
«строка → JSON» и параметры проверки (стоп-слова итогов, форматы даты, признак
знака расхода). Файл с ошибкой формата не загружается, а сервис стартует с
предупреждением в логе.

#### Scenario: Профиль загружен
- **WHEN** в `prompts/banks/` лежит `tinkoff.txt` с корректной разметкой
- **THEN** профиль `tinkoff` («Тинькофф») доступен для выбора и автоопределения

#### Scenario: Битый файл
- **WHEN** в `sber.txt` нет строки `# version:`
- **THEN** профиль `sber` не загружен, в логе `profile_invalid` с именем файла, остальные профили работают

### Requirement: Список профилей
`GET /api/ai/statement-profiles` SHALL возвращать встроенные профили (`id`,
`name`) и свои форматы пользователя (`id`, `name`, число примеров) для выбора
в форме загрузки.

#### Scenario: Список для формы
- **WHEN** у пользователя есть свой формат «CSV из Revolut» с 4 примерами
- **THEN** ответ содержит встроенные профили и `{id, name: "CSV из Revolut", examples: 4}`

### Requirement: Выбор профиля при создании
`POST /api/ai/imports` SHALL принимать необязательный `profile`: `auto` (по
умолчанию), `none` или `id` профиля. Неизвестный `id` даёт 400
`unknown_profile`. Выбранный или определённый профиль и его версия сохраняются
в импорте и отдаются в `GET /api/ai/imports/{id}` (`profile: {id, name,
source: auto|manual}`).

#### Scenario: Ручной выбор
- **WHEN** клиент создаёт импорт с `profile: "tinkoff"`
- **THEN** все фрагменты извлекаются с профилем `tinkoff`, в ответе `profile.source: manual`

### Requirement: Автоопределение
При `profile: auto` сервис SHALL сравнивать первые 40 строк текста с сигнатурами
встроенных профилей и с отпечатками своих форматов пользователя. Совпадение
ровно одного — профиль выбран. Ни одного или несколько — профиль не
применяется (как `none`), а в импорте указана причина
(`profile_detect: none|ambiguous`).

#### Scenario: Узнал банк
- **WHEN** в шапке выписки есть «АО «ТБанк»» и строка колонок из сигнатуры `tinkoff`
- **THEN** импорт идёт с профилем `tinkoff`, `profile.source: auto`

#### Scenario: Не узнал
- **WHEN** текст не совпал ни с одной сигнатурой
- **THEN** извлечение идёт общим промптом, `profile_detect: none`

### Requirement: Отпечаток формата
Для каждого импорта сервис SHALL вычислять отпечаток формата: sha256 от
нормализованной строки заголовка колонок (CSV — первая непустая строка;
текст и PDF — первая строка, где есть хотя бы три слова из словаря заголовков:
«дата», «сумма», «описание», «операция», «валюта», «остаток»). Цифры и даты
при нормализации отбрасываются. Нет такой строки — отпечатка нет.

#### Scenario: Тот же банк, другой месяц
- **WHEN** пользователь загружает CSV того же банка за октябрь после сентябрьского
- **THEN** отпечаток формата совпадает с сентябрьским

### Requirement: Профиль в промпте извлечения
Задание `extract_rows` SHALL получать подсказки и примеры профиля в системной
части промпта. Бюджет профиля — не больше `AI_PROFILE_MAX_TOKENS` (по умолчанию
500, оценка: символы / 3). Размер фрагмента уменьшается на тот же бюджет,
чтобы промпт с ответом укладывался в контекст модели.

#### Scenario: Фрагмент с профилем
- **WHEN** профиль занимает 450 токенов
- **THEN** фрагмент не длиннее `AI_EXTRACT_CHUNK_CHARS − 450 × 3` символов, а в системном промпте есть подсказки и примеры профиля

#### Scenario: Сумма против остатка
- **WHEN** в профиле сказано «последняя колонка — остаток, не сумма», а в строке «12.09 KOFE -200,00 15 300,00»
- **THEN** модель возвращает `amount: "200.00"`, и проверка подтверждает строку

### Requirement: Профиль в проверке
Параметры профиля SHALL дополнять проверку кодом: стоп-слова итогов
(для «не разобрано»), разрешённые форматы даты и признак знака расхода
(минус в сумме, отдельная колонка или слово «Списание»). Если по профилю знак
однозначен, он перекрывает `dir` модели.

#### Scenario: Знак по колонке
- **WHEN** в профиле расход отмечается словом «Списание», а модель вернула для такой строки `dir: income`
- **THEN** строка получает `dir: expense`

### Requirement: Свои форматы из правок
Когда пользователь правит у строки сумму, дату или направление
(`PATCH rows`), сервис SHALL сохранять пример «текст строк-источников →
исправленный JSON» в своём формате пользователя с отпечатком этого импорта.
Нет такого формата — он создаётся с именем по источнику (например,
«statement.csv»). Хранится не больше 5 последних примеров на формат.

#### Scenario: Первая правка
- **WHEN** пользователь исправил сумму строки в импорте с отпечатком формата F, своего формата для F ещё нет
- **THEN** создаётся формат пользователя с отпечатком F и одним примером

#### Scenario: Следующая выписка
- **WHEN** пользователь загружает выписку с тем же отпечатком F при `profile: auto`
- **THEN** профиль — свой формат F, его примеры уходят в промпт извлечения

### Requirement: Свой формат поверх встроенного
Если у импорта есть и встроенный профиль, и свой формат пользователя с тем же
отпечатком, подсказки SHALL браться из встроенного, а примеры — сначала свои,
затем встроенные, в пределах бюджета.

#### Scenario: Тинькофф с правками
- **WHEN** определён `tinkoff`, и у пользователя есть 3 своих примера для этого отпечатка
- **THEN** в промпт попадают подсказки `tinkoff`, 3 своих примера и встроенные — сколько влезет в бюджет

### Requirement: Управление своими форматами
`PATCH /api/ai/statement-profiles/{id}` SHALL переименовывать свой формат, а
`DELETE` — удалять его вместе с примерами. Встроенные профили не меняются
(403). Свои форматы не истекают по TTL импорта.

#### Scenario: Удаление
- **WHEN** пользователь удаляет свой формат «statement.csv»
- **THEN** следующие выписки с этим отпечатком идут без него

### Requirement: Приватность примеров
Примеры своих форматов SHALL храниться только в базе `ai`, видны только
владельцу и не попадают в логи. Встроенные профили содержат только
обезличенные примеры.

#### Scenario: Чужой формат
- **WHEN** пользователь запрашивает `PATCH /api/ai/statement-profiles/{id}` чужого формата
- **THEN** сервис отвечает 404
